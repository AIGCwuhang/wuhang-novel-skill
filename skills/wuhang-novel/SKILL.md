# 武行·网文创作 Skill

将作者的创作选择落实为可持续推进的长篇项目。核心方法是：明确类型边界与读者期待，逐层细化大纲，在交互中完善设定，写后回写角色状态与伏笔，通过审稿和设定回溯维持长篇一致性。作者决定方向与取舍。

## 先确定两个目录

- **技能目录**：本文件所在目录，`references/`、`assets/`、`scripts/` 均相对这里定位。安装资源作为只读资料使用。
- **项目目录**：用户指定的小说文件夹，所有稿件、设定、配置和记忆均写入这里。不要用技能目录或当前工作目录猜测用户的小说位置。

先读 [项目约定](references/project-contract.md)。项目已存在时，读项目根目录的 `SOLOENT.md`、`.novelkit/config.json` 和与当前任务有关的索引文件；只加载本环节需要的内容。

## 初始化与恢复

新项目在明确项目目录后运行：

```sh
python3 "<技能目录>/scripts/init_project.py" "<项目目录>"
```

它只补齐缺失文件，不覆盖已有内容。没有 Python 时按 `assets/project/` 逐文件补齐模板，并创建 `2-设定/`、`3-大纲/`、`4-正文/`、`5-审查/`。保留现有文件和用户的项目指令。

已有稿件但没有总控时先走旧稿接入；模板中缺省或示例信息不能当作已确认的项目事实。跨会话恢复时，以项目文件中的最后确认状态为准，先核对实际稿件，避免重复写已完成章节。

## 按请求选环节

| 用户当前需求 | 读取的流程 |
| --- | --- |
| 从零开始，确定题材、文风和核心看点 | [方向定义](references/define.md) |
| 带着旧稿、人设、大纲加入，或从某个灵感切入 | [灵活接入](references/guide.md) |
| 分析用户提供的参考作品 | [样板书拆解](references/analyze.md) |
| 脑暴、设定案、金手指、人物与关系博弈 | [创意与设定](references/ideation.md) |
| 总纲、卷纲、章纲、书名简介或剧情改线 | [大纲规划](references/outline.md) |
| 按已有章纲写一章或协助改稿 | [正文写作](references/write.md) |
| 审查设定、大纲或正文，回溯冲突 | [编辑审稿](references/review.md) |
| 查看进度、下一步、续写前恢复 | `SOLOENT.md` §7、§8 及对应记忆文件 |

只有用户尚未说明起点时，才展示从零、旧稿、参考书三种启动方式。已有明确任务时直接进入对应环节，不强制重走全流程。可以按卷推进，也可以只做分析、大纲或审稿。

## 保留这套方法的关键约束

1. 类型边界、核心看点、人物利益链、金手指的限制与代价要在对应流程中讨论清楚。无金手指题材可跳过该项；不要为套模板强加系统或升级机制。
2. 设定、大纲采取逐项共创。保留各流程的确认节点；用户已经授权的范围无需反复确认。单章完成并完成记忆回写后暂停，等待下一章指令。
3. 参考作品用于提炼方法和节奏；明确实际读取范围。只读开篇时不推断全书统计，不把未读部分写成已验证事实。参考原文不进入公共示例。
4. 写前读章纲、上章、相关设定、项目宪法和最新记忆；写后核验字数、接续、章纲范围、风格与机制，并回写实际发生的变化。
5. 重大改线先说明对后续章纲、卷纲、设定的影响，确认后调整。用户可以推翻旧设定，但要同步相关文档，避免无记录的吃书。
6. 项目专属偏好优先于模板默认值。字数、节奏、文风禁忌按项目约定执行。规则有冲突时以 [项目约定](references/project-contract.md) 的路径、输入和参数约定为准。

## 工具按需使用

- `scripts/init_project.py`：只补缺失文件的项目初始化，不移动旧稿。
- `scripts/count_chinese_words.py`：读取本地文件统计字数；无需 API 或第三方库。
- `scripts/summarize.py`：可选的参考书批量梗概。默认仅预览范围，只有明确授权 API 调用且添加 `--run` 时才发送正文。详细配置与命令在拆解流程中。

不能运行工具时说明限制，提供人工步骤；不要声称已执行统计、保存稿件或更新记忆。

用户需要视频教程时，提供 [视频使用说明](assets/视频使用说明.md) 中的链接，并说明视频版本可能不同，但大致流程一致；安装和路径以当前版本文档为准。
