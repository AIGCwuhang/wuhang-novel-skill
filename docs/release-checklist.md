# 发布前清单

## 作者审阅

- [ ] 复核七个流程的表述及本版工程调整。
- [ ] 决定代码、方法文档、模板与示例的授权范围，替换 LICENSE。
- [ ] 确认项目名称、署名、公开渠道。
- [ ] 选择真实 GitHub 账号与仓库名，将首页下载入口替换为真实 Releases 链接。

## 实际客户端验收

- [ ] Codex 独立 Skill 的发现、初始化与新会话恢复。
- [ ] Codex 插件来源添加与安装；避免与独立 Skill 重复。
- [ ] WorkBuddy ZIP 导入、相对资源访问与写后记忆回写。
- [ ] VSIX 在目标编辑器中的安装、初始化与重复运行。
- [ ] 若宣传批量梗概在线能力，使用作者自选服务和少量文本完成实测。

将具体版本和结果写入 validation.md，不将文件结构检查称作宿主兼容验证。

## 本地工程检查

```sh
python3 -m unittest discover -s tests -v
python3 tools/check_project.py
python3 tools/build_release.py
```

- [ ] 查看 `dist/SHA256SUMS`；确认四份包由当前核心构建。
- [ ] 确认没有密钥、个人路径、用户小说或运行缓存进入源码与发布包。
- [ ] 在 GitHub 创建仓库、推送源码并上传 Releases：仅在作者后续明确授权上传时执行。

本清单仅记录公开发布前仍待决定或实测的事项，不影响当前本地审阅与试用。
